# CrimeLens AI - Backend

Backend API and machine learning service for **CrimeLens AI**, a crime analysis, visualization, risk assessment, and forecasting platform.

The backend provides APIs for crime case management, analytics, district-level risk assessment, hotspot detection, and ML-based crime forecasting.

## Tech Stack

- Python
- FastAPI
- MongoDB
- PyMongo
- Pandas
- Scikit-learn
- Joblib
- Uvicorn
- Pydantic
- Swagger / OpenAPI

## Features

- Crime case CRUD operations
- Case filtering
- Crime analytics
- District-level risk assessment
- Crime hotspot detection
- ML-based next-month crime forecasting
- Police-station-level crime prediction
- District-level aggregated forecasting
- Low / Medium / High station risk classification
- MongoDB integration
- Historical ML dataset support
- CORS configuration
- Interactive Swagger API documentation

## Setup

### 1. Navigate to the backend

```bash
cd backend
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

### 3. Activate the virtual environment

Windows PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

### 4. Install dependencies

```bash
pip install -r requirements.txt
```

### 5. Configure environment variables

Create a `.env` file inside the `backend` directory and configure the required MongoDB connection settings.

Do not commit `.env` files containing credentials.

### 6. Seed historical ML data

Crime forecasting uses the ML-ready dataset located at:

```text
data/crimelens_karnataka_dataset_v2_ml_ready.csv
```

From the `backend` directory, run:

```bash
python seed_historical_data.py
```

This loads the historical dataset into the MongoDB collection:

```text
historical_cases
```

The current dataset contains approximately 50,000 historical crime records.

### 7. Run the backend

```bash
uvicorn app.main:app --reload
```

The API runs locally at:

```text
http://127.0.0.1:8000
```

## ML Crime Forecasting

CrimeLens uses a supervised machine learning model to forecast the expected number of crimes for the next month.

The forecasting model operates at the **police-station level**.

District forecasts are generated by aggregating predictions from the police stations belonging to the requested district.

### Model

The production model is:

```text
RandomForestRegressor
```

The trained Scikit-learn pipeline is stored at:

```text
app/ml/models/crime_risk_model.joblib
```

The model was selected after comparison with:

- Naive persistence baseline
- Random Forest
- Extra Trees
- Gradient Boosting

Random Forest produced the best MAE on the time-based test set.

### Training Strategy

The dataset is split chronologically:

```text
Training: 2020-2022
Testing:  2023
```

This prevents future test-period observations from being used to train the model.

Each training observation represents one police station for one month.

The prediction target is:

```text
next_month_crime_count
```

### Model Features

The model currently uses:

```text
district
police_station
year
month
high_severity_count
latitude
longitude
previous_month_crime_count
lag_2_crime_count
lag_3_crime_count
rolling_3_month_avg
crime_trend
```

The additional lag and trend features provide recent temporal context to the forecasting model.

### Model Evaluation

Current Random Forest performance on the 2023 test set:

| Metric | Random Forest | Naive Baseline |
| --- | ---: | ---: |
| MAE | 5.18 | 6.26 |
| RMSE | 7.26 | 8.29 |
| R² | 0.229 | -0.004 |

The Random Forest improves MAE by approximately **17.20%** over the naive persistence baseline.

The metrics indicate that the model improves over the baseline, while forecasting uncertainty remains significant and predictions should be interpreted as analytical estimates rather than exact future crime counts.

### Station Prediction

```http
GET /api/predictions/station
```

Example query:

```text
police_station=Krishnaraja Ps
```

Example response structure:

```json
{
  "district": "Mysuru",
  "police_station": "Krishnaraja Ps",
  "latest_data_year": 2023,
  "latest_data_month": 11,
  "predicted_next_month_crime_count": 16,
  "risk_level": "Low"
}
```

### Station Risk Classification

Station risk levels are based on the historical distribution of monthly police-station crime counts.

The 33rd and 67th percentile values are:

```text
33rd percentile = 16
67th percentile = 23
```

Therefore:

| Predicted monthly crimes | Risk |
| --- | --- |
| 0-16 | Low |
| 17-23 | Medium |
| 24+ | High |

### District Prediction

```http
GET /api/predictions/district
```

Example query:

```text
district=Mysuru
```

The district endpoint:

1. Finds police stations belonging to the district.
2. Generates an ML forecast for each station.
3. Aggregates the station predictions.
4. Returns the total forecast and station risk distribution.

Example response structure:

```json
{
  "district": "Mysuru",
  "station_count": 4,
  "predicted_next_month_crime_count": 65,
  "risk_summary": {
    "low": 3,
    "medium": 1,
    "high": 0
  },
  "station_predictions": []
}
```

## ML Training

Training utilities are located in:

```text
app/ml/training/
```

### Prepare training data

```bash
python app/ml/training/prepare_training_data.py
```

### Compare models

```bash
python app/ml/training/compare_models.py
```

### Train the production model

```bash
python app/ml/training/train_risk_model.py
```

Training the production model overwrites:

```text
app/ml/models/crime_risk_model.joblib
```

Model changes should therefore be evaluated using the comparison script before replacing the production model.

## MongoDB Collections

```text

historical_cases
    Historical ML-ready records used for forecasting.
```
